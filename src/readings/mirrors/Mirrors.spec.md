# Mirrors

The mirror reading: the lists a project keeps by hand that must mirror something defined elsewhere (the defect family hand-list), found by overlap between literal collections and what code derives (a folder's files, the import closure of a list of files, a module's exports, the keys a file reads), explained by git history, read from git objects at one revision, and counting the restatements nothing holds equal; advisory: on request through query mirrors, and at a session's start from the last reading kept, never one taken in a hook.

## invariants
- reads one revision: The mirror reading reads every file from git objects at one revision, HEAD unless another is asked for, and never the working tree, so an edit not yet committed changes nothing it says and an older revision reads as it was committed.
  over: a fixture repository whose list of files drifts from its import closure in its last commit, read at HEAD with an uncommitted edit that repairs the list, and read at the commit before
  via: the mirror reading reads git objects at its revision: an uncommitted edit leaves it unchanged, and the commit before reads as it was
  because: an agent edits the tree mid-session, and a reading of a half-made edit would name drift the edit is about to repair or miss drift it is about to commit; read at a revision it holds still, and a release can be read as it shipped, which is how the spike measured BROWSER_SOURCES at v1.7.1 and at b37627e (d-577a281e, d-520846aa)
  crossing: project-source -> reading
  refuted: made readAll take each file's text from the working tree instead of the object at the revision -> the totality oracle went red; restored, green (2026-10-12)
  kinds: none
- never computed in a hook: No hook takes the mirror reading: no module the hooks load at run time reaches the reading or the compiler's parser; orient names hand lists only from the last reading kept, labeled with the commit and time it read; write-time advice only looks a write up in the advice index that reading kept (advice.ts, which parses nothing); and the session start and stop start a new reading detached, never waiting on it.
  over: every module the command line and the hook module import at run time, followed to the end, and orient over a kept reading and over none
  via: no hook loads the mirror reading: the hooks' import closure never reaches it or the compiler, and orient reads only the kept reading, labeled with its commit
  because: a tool hook's latency budget is 3 s and the start injection has a fixed budget; the reading takes about a second on Coherence and grows with the project and its history, so a hook that took it would spend its budget on advice (d-520846aa). The label keeps a reading of an older commit from being taken for a reading of the tree now. Write-time advice was asked for by the owner (reversing d-bb20df40): it reads the kept index, a lookup of milliseconds, so the full reading still never runs in a hook
  crossing: record -> reading
  refuted: imported readMirrors statically into recorded.ts, the module the hooks load for orient -> the totality oracle went red; restored, green (2026-10-12)
  kinds: none
- only strong groups are surfaced: A group is put in front of the agent (orient, and query mirrors by default) only when its sets lie in more than one file, one finding shares three or more names, and it scores 20 or more; every other group is listed only on request, and nothing the reading finds is a spec problem or blocks.
  over: a group beside its source in one file, a two-name group, a group under the score, a group that passes all three, the kept reading, and the default and --all answers
  via: only cross-file groups sharing three or more names and scoring 20 or more are surfaced, and the rest are listed only on request
  because: d-9f7c91c8: at v1.7.2 this cut surfaces 26 of 82 groups, 18 of them hand lists, and 10 of the 16 hand lists the manual sweep found, while two-name groups (5 of 34) and same-file groups (2 of 23) were mostly no mirror.   kinds: none

- restatements are counted: The mirror reading counts as a restatement each value written at live sites in two or more files, a literal or two sets that share members or differ by at most one, when what the copies share says enough: the summed rarity of its tokens, in bits under the project's own code and the identifiers of TypeScript's library typings, is 18 or more, so a short rare value counts and a common word never does; it leaves out the project's test files and fixtures, a value a literal type names, prose of four or more spaces unless a named constant holds it in two or more files, a pattern whose words and shape say too little (a regular expression weighs its literal words' bits and a bit and a quarter per other character, so a bare `[0-9a-f]{8}` is left out and a whole seventeen-character pattern written twice is not), and strings another party defines (URLs, MIME types, language server methods, HTTP's header names, methods and status phrases, git's subcommands, ARIA attributes, HTML character references); it ranks what has already diverged first, then copies history shows changed apart, then copies that changed together, then copies that never changed, copies across parts of the project first within each; and query mirrors says the counts in its default answer, lists them with --restatements and carries them in its JSON.
