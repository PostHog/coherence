## Refusals

There were none from the authority model, and the code explains why. `transitionWork`, `handoffWork` and `closeWork` in `src/coordination/work.ts` (lines 1054-1130) never compare the writer (`--session/--agent`) to `item.owner`, and nothing checks whether the writer is an orchestrator. The only write-time refusals that exist are: unknown work id, terminal state, no-op transition, handoff to the current owner, `completed` without `--evidence`, and an `expectedPrevious` mismatch **only when the caller passes `--expected-previous`**. "Exact session" means `session !== "unknown"`. Authority (`kind`, `grantedBy`, `boundary`) is validated for shape and then only rendered. Conjecture d-dd490683 (2026-09-15, session `5ebd0735`) already records the grantedBy half of this; the owner half is the same class.

Three episodes show the model being bypassed without any refusal:

1. **Curator writes under the parent's session (2026-09-09T14:46:51Z, Codex thread `01a086a2`).** Its own SessionStart said `YOUR SESSION ID IS 01a086a2-…`. It ran `work inspect wrk-guarantee-curation-r1`, saw `owner: 01a06cfd-… (guarantee_curator)`, and ran `work transition wrk-guarantee-curation-r1 active --session 01a06cfd-b3bc-7771-b2fb-a270ead577b7 --agent guarantee_curator` — the orchestrator's session id. Accepted (`wev-06cceb3c861f3f49`), appended to main's file. Main noticed 64 s later and handed the order to the child's real session ("align assignment with actual writer identity rather than parent-session labeling"). Not an overstep in intent, but exactly the spoof the hook says cannot happen, and the ledger accepted it.
2. **Sol and Terra do the same on 2026-09-14** (threads `01a0a040`, `01a0a041`; each hook printed its own id). Both transitioned and closed `wrk-scope-story-sol` / `-terra` with `--session 01a0912a-…` (main's). Terra also passed `--agent main`. All four writes accepted; the ledger now says main's session did Terra's work.
3. **Claude subagents hand orders to themselves (09-15 and 09-17, seven times).** Main's dispatch prompt literally instructs: "take it: `work handoff <id> --owner-session <YOUR SESSION ID> --owner-agent scope_shell --because "dispatched by main" --session <YOUR SESSION ID>`". Every subagent complied; every handoff was accepted with `fromOwner = main`, written by the successor. Two of them (`scope_shell` 20:39:47Z, `scope_readings` 20:40:18Z) omitted `--agent`, so the record says `agent: "main"` — the CLI default at `src/cli.ts:801` — and the ledger attributes those two handoffs to main.

Verdict on each: none was an agent overstepping its brief; all were legitimate agents routing around a rule that cannot be satisfied at dispatch time (the orchestrator does not know a child's host-issued session id before spawning it). The rule produced no refusal, no obstacle, and no protection. What it produced is mis-attribution in the durable record.

## Assessment

The authority model is described in the hook and then not enforced by the ledger, and the transcripts show agents discovering that in the only way available to them: by doing the thing the hook says they cannot. The hook's three claims — only an orchestrator creates or hands off work, owners advance only their exact assignment, predecessor tokens expire — correspond to zero code paths that compare writer to owner or grantor, an optional `--expected-previous` that only the assigned session is ever told about, and no liveness. In this repo every handoff since 09-15 was written by the successor to itself on main's instruction (`ff013915` dispatch prompts, 09-15T20:39Z onward), three Codex children wrote under main's session id (`01a086a2` 09-09T14:46Z, `01a0a040`/`01a0a041` 09-14T14:10Z), and two Claude records attribute a subagent's handoff to `main` because `--agent` defaulted. Zero refusals in ~1,000 work commands across every transcript. The ceremony has a real cost: every subagent's first minute is `work inspect`, a self-handoff, a `transition active` (with one `--because` retry in two of five cases), and every orchestrator turn re-runs `orient; work inspect`. What survives on its own merits is not authority but the order text: `objective`, `criteria`, `boundary` and `writeScopes` are what subagents actually read (`work inspect <id>` opens every subagent transcript) and what let `orient` flag one genuine write conflict on 09-15.

Consequences are doing nothing in this repo that inferred session-to-work binding would not do better. The 16 links exist because the session that built the feature exercised it once on 08-20; every one restates a `close` reason or a verification label already recorded elsewhere, written by the same session within the hour. No later session added a link, and no session anywhere ran `consequence inspect` in this repo. The one place the ledger has been active is negative: since 09-09 `orient` has demanded a verification→work link for every completed order, agents have read that heading at least seven times, and the response was to rewrite the rule (receipts, d-d9d2d8e5) rather than write a link. In the bakeoff repos where `consequence add` was used ~55 times, the writer was always the closing session and the edge was `this work implements/verifies the decision I just made`, which is exactly the binding a reader could infer from the work record's `session`, `at`, and the decision journal's `--work` field. The question the ledger was built to answer — d-fd82d683 measured "zero durable cross-ledger consequence relationships" — is still answered by zero organic instances 28 days later; by the project's own rule (count instances before keeping a concept), that is a finding, not a feature.

If the owner wants one intervention each: for authority, either make `handoffWork`/`transitionWork`/`closeWork` refuse when `request.session !== item.owner.session` and let the orchestrator create with `--owner-session` after spawn (main already does this on 09-15), or delete the three hook sentences that claim enforcement that does not exist; for consequences, replace the `verifies` edge with the receipt's own `--work` binding (already recorded by `verify --receipt --work`, used 5 times since 09-11) and let `orient` read receipts instead of links.
