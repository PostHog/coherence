# Coherence promo — narration

What if the best way to save tokens

Is to stop writing bad code?

Our industry is lost in a fog.

We have completely new tools for building software, and we can build it faster than ever.

But our processes have never been more confused. The work we do is more opaque, more complex, more difficult to reason about than at any point in our careers.

We can imagine new code, we can describe thoughtful architecture, we can specify sturdy systems.

But we have no idea how faithfully our robots are building for us. The more complex our designs, the more challenging they are to validate.

Agents are writing good code by accident.

The systems at our disposal are trained to finish the job at any cost, so they cut subtle corners where we can’t see.

Understanding it all requires reading code and reasoning about its consequences, but every day there’s just more.

More complexity than we can possibly get our arms around.

Our solution? Throw more inference at the problem. We use inference to write code, then we use more inference to ask if the code we wrote was good.

So what do we get for all this? Bugs that recur. Endless whack a mole adversarial reviews.

OpenRouter does twenty trillion tokens a day. GitHub struggles to stay online.

Software staggers under this scale of motion.

Because we don’t yet have the tools to make sense of this new world.

It's time to build the next generation of tools.

Developers need clarity and confidence, not just speed.

The race is on to deliver. Coherence lets us compete.

We start with clear definitions.

Language models are built out of language. Clearly defining your terms changes their behavior. Agents start to do what you meant, not just what you said.

This impacts the integrity of what gets built, making bugs easier for agents to detect.

But we can do more.

The Coherence decision journal compresses hundreds of thousands of tokens into a handful of decisions.

If a bad call happened in the process, it’s right there in the history, instead of buried in code.

Quickly move between different conversations and agents without costly handoff files, while letting subagents compare notes.

And decisions are never buried in a long transcript.

We also need constant confidence that our code matches our intentions.

Coherence uses your language server to detect security bypasses. The moment an agent writes code that touches something sensitive without routing through a designated chokepoint, the project goes red.

The agent discovers the violation immediately.

Instead of enforcing security through implicit conventions, we know our intentions are represented in the structure of our projects themselves.

But how do we check that the agent did what we want?

The Coherence structure view shows you the entrypoints into your project, its major components, and how those components interact with each other. Always accurate and up to date.

When chokepoints are violated, you’ll see it.

When a major change alters the relationships between components, you’ll see that too.

No more sifting through thousands of lines of code to understand what was built or changed. See your project as it is right now.

These are the kinds of tools we need to clear the fog.

Spend less inference on code that doesn’t work, less inference detecting bugs, less inference investigating the decisions that went into your changes.

So if you’re ready to try a new way of working with agents, come join us building the software of 2030.
